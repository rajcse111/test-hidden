### Goal

A local document Q&A assistant: I add my own **PDF, DOCX, and Excel (.xlsx)** files, the app ingests them into a vector database using a local embedding model, and then I can ask questions and get answers that are **grounded in my documents with citations** — generated by my **local Ollama server**, in natural language, but constrained to the facts in the retrieved context. If the answer isn't in the documents, it must say so rather than inventing one.

### Hard requirements

- **Language:** Python 3.14.3.
- **Fully local:** no cloud APIs, no API keys. Everything runs offline on a 16 GB RAM laptop (likely CPU-only, possibly with a GPU).
- **LLM + embeddings via Ollama:**

  - Generation model: `llama3.1:8b` (configurable; allow smaller like `llama3.2:3b`).
  - Embedding model: `nomic-embed-text` (configurable). Use the same model for indexing and querying.
  - Use the official `ollama` Python client. Support **streaming** responses.
- **Vector database:** **ChromaDB** with a **persistent client** (persists to `./storage`), so ingestion is done once and survives restarts.
- **Document ingestion:** support **PDF** (`pdfplumber`), **DOCX** (`python-docx`), and **Excel** (`pandas` + `openpyxl`). For Excel, serialize each row into a self-describing sentence (`"Sheet <name> | Col: val | Col: val"`) so it embeds meaningfully. Skip empty content. Capture **metadata** per chunk: `source` (filename), `page` or `sheet`, and `chunk_id`.
- **Chunking:** recursive splitter (`langchain-text-splitters` `RecursiveCharacterTextSplitter`) with **configurable chunk size (

  ~800 chars) and overlap (~120 chars)**.
- **Idempotent ingestion:** hash file contents (or chunk text) so re-ingesting an unchanged file does not create duplicates; print a clear summary (files processed, chunks added, chunks skipped).
- **Retrieval:** embed the query, fetch **top-k (default 4, configurable)** chunks from ChromaDB, return documents + metadata + similarity scores.
- **Prompt construction / context injection:** a system prompt that (a) sets the assistant role, (b) injects the retrieved chunks **clearly labeled with their source/page**, (c) instructs the model to answer **only** from the context, to answer conversationally in its own words, to **cite sources as `[source, page]`**, and to reply `"I don't know based on the provided documents."` when the context is insufficient. Keep temperature low (≈0.2).
- **Two interfaces, both wired to the same core:**

  1. **CLI** (`cli.py`, use `typer`): commands `ingest <path>` (file or folder), `chat` (interactive REPL with streaming answers + printed citations), and `reset` (clear the vector store). Use `rich` for readable output.
  2. **Streamlit web UI** (`web.py`): a file-uploader (PDF/DOCX/XLSX) that ingests on upload, a chat box, streamed answers, and an expandable "Sources" section showing the retrieved chunks. Keep it ~simple.
